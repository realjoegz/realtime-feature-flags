# Evidence

Each row states a claim and links the tests that check it. `npm run verify` runs `scripts/check-claims.mjs` after the tests, and it fails unless every linked test ran and passed in that run.

A test whose name ends in "(seed S, N runs)" runs fast-check with that seed and that number of runs. A control test runs the same property against a committed broken evaluator in `packages/core/test/controls/` and passes only when the property fails there.

The API rows sign their tokens with key pairs made for the test run, whose key set the API fetches over HTTP from a local server (`apps/api/test/support/idp.ts`), as it fetches Dex's.

The SDK client rows run the client against a fetch that each test drives (`packages/sdk/test/support/fake-stream.ts`). The stream rows read GET /sdk/stream with fetch and the SDK's parser, and the convergence and agreement rows run SDK clients over fetch, against one Nest app, or two in one process on separate ports, listening on 127.0.0.1 on a database of their own built from the migrations. The apps of one test share that database and a Redis key and channel prefix of their own, as two replicas do. The wake-up test drives the fan-out directly, with a reader that the test holds at each read. Faults in the notifications between apps (`apps/api/test/support/bus-faults.ts`) are a notification that one app's subscriber never hears, a publish that throws, and an app's subscriber connection closed by Redis with CLIENT KILL.

The tenant isolation rows run one detector per check over every table that rff_app can reach. Their controls run the same detectors against subjects that leak (the superuser connection, a table without row-level security, tables whose policies have one defect each, and the broken look-up functions in `apps/api/test/fixtures/isolation/`) and pass only when the detectors report them.
